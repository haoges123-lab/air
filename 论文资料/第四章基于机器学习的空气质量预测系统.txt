# 第四章 空气质量预测系统实现

## 4.1 系统设计背景与目标

### 4.1.1 系统设计背景

随着我国大气污染防治工作的深入推进，空气质量监测网络日趋完善，数据积累日益丰富。公众对空气质量信息的需求也在不断增长，不仅关注当前的空气质量状况，更希望了解未来空气质量的变化趋势，以便合理安排出行和日常活动。同时，环境管理部门也需要科学的预测工具来辅助决策，提前采取应对措施。

在此背景下，本研究设计并实现了一个功能完备的空气质量预测系统。该系统不仅能够展示全国各城市的实时空气质量数据，还能够基于深度学习模型预测未来空气质量，并为公众提供健康建议。系统的设计与实现遵循以下原则：

第一，数据驱动的原则。系统以实时空气质量监测数据为基础，充分利用数据可视化技术，为用户提供直观、准确的信息展示。

第二，用户导向的原则。系统界面设计简洁友好，操作流程清晰易懂，普通公众无需专业知识即可使用。预测结果配有直观的图表和易理解的健康建议。

第三，服务化的原则。系统以后端API服务的形式提供预测能力，便于与其他系统集成，也为未来功能扩展预留了接口。

第四，可扩展的原则。系统采用模块化设计，各功能模块之间松耦合，便于后续的功能升级和性能优化。

### 4.1.2 技术框架概述

本系统的技术架构采用前后端分离的B/S模式，后端使用Python FastAPI框架提供RESTful API服务，前端使用HTML/CSS/JavaScript实现页面交互和数据可视化。

后端技术栈包括：FastAPI作为Web框架，提供API路由和请求处理功能；PyTorch作为深度学习框架，负责模型的加载和推理；Requests库用于调用外部空气质量API获取实时数据；JSON作为数据交换格式，便于前后端数据交互；Uvicorn作为ASGI服务器，提供高性能的HTTP服务。

前端技术栈包括：HTML5和CSS3实现页面结构和样式；ECharts作为数据可视化库，提供丰富的图表组件；JavaScript实现页面交互逻辑和API调用；GeoJSON存储中国地图的地理数据。

系统的整体架构分为三层：数据层负责获取和管理空气质量数据；业务层负责数据处理、模型预测等核心逻辑；展示层负责用户界面和数据可视化。

### 4.1.3 系统功能模块

本系统的功能模块包括：

（1）全国空气质量地图可视化模块：在地图上以散点形式展示全国各城市的空气质量状况，用不同颜色标识不同的空气质量等级，用户可以缩放和平移地图查看感兴趣的区域，点击城市可查看详情。

（2）城市空气质量详情模块：展示选中城市的实时空气质量数据，包括AQI、各污染物浓度、空气质量等级、首要污染物等信息，还包括24小时污染物浓度变化趋势图。

（3）历史数据查询模块：提供城市历史空气质量数据的查询功能，用户可选择日期范围和污染物类型，以柱状图形式展示历史趋势。

（4）空气质量预测模块：基于深度学习模型预测未来一天的空气质量，以卡片形式展示预测结果，包括各污染物预测值、AQI预测值和预测等级，并配以雷达图和柱状图进行可视化展示。

（5）健康建议模块：根据空气质量预测结果，自动生成针对性的健康建议，包括对普通人群和敏感人群的不同建议，以及户外活动和防护措施的建议。

## 4.2 系统架构设计

### 4.2.1 整体架构

本系统采用前后端分离的架构设计，前后端通过HTTP API进行通信。这种架构的优势在于：前后端可以独立开发和部署，便于团队协作；后端服务可以同时支持多个前端应用（如Web端、移动端）；后端逻辑与前端界面解耦，便于逻辑复用和测试。

系统的整体架构包含以下层次：用户通过浏览器访问前端页面，前端页面通过Ajax请求调用后端API，后端处理请求并返回JSON格式的数据。对于实时数据展示，后端从外部API获取数据并缓存；对于预测功能，后端加载训练好的模型进行推理。

后端服务采用FastAPI框架实现。FastAPI是一个现代化的Python Web框架，基于Starlette框架构建，支持异步请求处理，具有高性能、易用性和自动文档生成等特点。FastAPI的路由系统使API设计清晰直观，请求处理函数使用类型提示提高了代码的可读性和可靠性。

前端页面采用单页面应用（SPA）的设计理念，通过JavaScript动态切换页面内容，无需刷新整个页面。这种设计提供了流畅的用户体验，页面切换无闪烁。导航栏位于页面左侧，包含地图视图、城市列表和空气质量预测三个主要入口。

### 4.2.2 数据流程

系统的数据流程可以分为实时数据流和预测数据流两条主线。

实时数据流的流程如下：外部空气质量API → 后端缓存 → 前端展示。具体而言，后端定时（可配置）从中国环境监测总站的API获取全国城市的实时空气质量数据，存入本地缓存（同时保存到JSON文件和内存缓存）。前端通过API调用获取数据后，使用ECharts在地图和图表中展示。

预测数据流的流程如下：用户请求 → 后端获取历史数据 → 模型推理 → 结果返回 → 前端展示。用户选择城市并发起预测请求后，后端首先根据城市名称查找对应的省份（因为模型是按省份训练的），然后调用数据接口获取该省份最近30天的历史数据，进行标准化处理后输入模型进行推理。预测结果经过反标准化处理后返回前端，前端以图表形式展示。

### 4.2.3 数据存储设计

系统使用文件系统存储数据，不需要传统意义上的数据库。数据以JSON格式存储在文件系统中，便于读写和处理。

主要的数据文件包括：

（1）city_air_data.json：存储全国城市的实时空气质量数据，包含城市名称、经纬度、AQI、各污染物浓度等信息。

（2）处理后数据/（省份名.json）：各省份的日均值数据，按日期排序，用于模型训练和推理。

（3）模型权重文件（weights/best_model.pt）：训练好的模型权重，包括模型参数、标准化参数、省份映射关系等。

这种文件系统的存储方式简单高效，适合本系统的数据规模和访问模式。数据量不大（约几十MB），文件读取速度可以满足实时性需求。

### 4.2.4 API接口设计

系统后端提供以下API接口：

（1）GET /api/cities：获取全国城市实时空气质量数据。返回所有有效城市的实时数据列表，包含城市名称，省份、AQI、污染物浓度等信息。

（2）GET /api/cities/24h?cityname={城市名}：获取城市24小时历史数据。返回指定城市过去24小时各污染物的逐时数据。

（3）GET /api/cities/history?cityname={城市名}&start={开始日期}&end={结束日期}：获取城市历史数据。返回指定城市在日期范围内的日均数据。

（4）GET /api/provinces：获取省份列表及所含城市。返回全国各省份及其包含的城市列表。

（5）GET /api/cities/predict?cityname={城市名}：预测城市未来空气质量。调用深度学习模型预测指定城市明日的空气质量，返回各污染物预测值和AQI。

（6）GET /china_map.json：获取中国地图GeoJSON数据。返回用于ECharts绑定的地图数据。

所有API接口均返回JSON格式的数据，包含状态码（code）、数据（data）和可选的消息（msg）字段，便于前端统一处理。

## 4.3 核心功能实现

### 4.3.1 数据获取与处理

数据获取模块负责从外部API获取空气质量数据，并进行必要的预处理。

外部数据源采用中国环境监测总站的空气质量API。该API提供全国城市的实时空气质量数据、六项污染物的逐时数据、历史日均数据等，数据权威可靠，更新频率高。

数据获取的实现采用异步请求和缓存机制。后端服务启动时自动从API获取全量数据并缓存，后续请求优先返回缓存数据以提高响应速度。缓存设置过期时间（如5分钟），过期后自动刷新获取最新数据。对于24小时数据和历史数据，采用按需获取的方式，避免不必要的数据传输。

数据预处理包括以下步骤：数据格式统一，将API返回的各种格式转换为系统内部统一格式；缺失值处理，对于缺失的污染物数据，采用该城市的历史均值填充；异常值过滤，对于明显异常的数据（如负数浓度），进行标记或修正；城市信息补全，根据城市名称补全省份归属、经纬度等辅助信息。

### 4.3.2 模型推理实现

模型推理模块负责加载训练好的模型，执行预测计算并返回结果。

模型推理的流程如下：接收预测请求 → 获取省份信息 → 准备输入数据 → 加载模型 → 执行推理 → 处理输出 → 返回结果。

省份信息获取是关键步骤。由于模型按省份训练，预测时需要知道目标城市属于哪个省份。系统维护了一个城市到省份的映射表，根据城市名称查找对应的省份。如果城市名称匹配不上（如少数民族地区的特殊地名），则尝试模糊匹配或返回错误。

输入数据准备包括：获取该省份最近30天的历史数据；提取时间特征（年周期、周周期、月周期、季节）；进行标准化处理（使用训练时保存的均值和标准差）。标准化参数按省份分别存储，确保处理的正确性。

模型加载采用延迟加载策略，在首次预测时才加载模型到内存，避免启动时占用过多资源。模型推理使用PyTorch的inference模式（torch.no_grad()和model.eval()），关闭梯度计算和Dropout，提高推理速度。

输出处理包括：提取模型输出的7维预测向量；对预测值进行反标准化，恢复到原始量纲；根据污染物的不同（预测难度）应用融合策略（对于PM2.5、PM10、AQI使用朴素基准）；计算预测AQI和空气质量等级。

### 4.3.3 前端可视化实现

前端可视化模块使用ECharts实现各类图表的渲染。

全国空气质量地图使用ECharts的geo地理坐标系组件。地图数据使用中国地图GeoJSON格式，通过echarts.registerMap注册为'china'地图。城市数据以散点形式叠加在地图上，每个散点的颜色根据AQI值映射到不同的空气质量等级颜色。散点大小也与AQI值成正比，使污染程度更加直观。

用户交互方面，支持鼠标滚轮缩放、鼠标拖拽平移，缩放级别较高时显示城市名称标签。点击城市散点弹出详情卡片，展示该城市的实时数据。

24小时趋势图使用折线图组件，横轴为时间，纵轴为污染物浓度。同时展示多条曲线（不同污染物），每条曲线使用不同颜色区分。图表支持鼠标悬停提示（Tooltip），显示具体数值。

预测结果展示使用卡片式布局，顶部展示城市名称、预测日期和AQI预测值及等级；中间以雷达图展示各污染物浓度相对于"严重污染"标准的比例，以柱状图展示各污染物的具体数值；底部展示根据预测结果生成的健康建议。

### 4.3.4 健康建议生成

健康建议模块根据空气质量预测结果，自动生成针对性的健康建议。

建议生成考虑以下因素：预测的AQI等级和主要污染物；各污染物的具体浓度；不同人群（普通人群、敏感人群）的健康敏感性。

建议内容的生成采用规则模板方法。根据AQI等级（优、良、轻度污染、中度污染、重度污染、严重污染）和首要污染物类型，从预设的模板库中选择相应的建议内容。模板内容包括：空气质量总体评价、污染物问题描述、不同人群的具体建议、户外活动建议、防护措施建议。

## 4.4 系统架构与核心代码

### 4.4.1 模型定义代码

以下是模型的核心实现代码，展示了双向LSTM空气质量预测模型的结构：

```python
class AirQualityModel(nn.Module):
    def __init__(self, num_provinces, seq_len=30, seq_input_dim=17,
                 hidden_size=64, num_layers=1, dropout=0.2, embed_dim=16):
        super().__init__()
        # 省域嵌入层，将省份ID映射为embed_dim维向量
        self.province_embed = nn.Embedding(num_provinces, embed_dim)

        # 双向LSTM层
        self.lstm = nn.LSTM(
            input_size=seq_input_dim,
            hidden_size=hidden_size,
            num_layers=num_layers,
            batch_first=True,
            bidirectional=True,
            dropout=dropout if num_layers > 1 else 0.0,
        )

        # 全连接输出层
        self.fc = nn.Sequential(
            nn.Linear(hidden_size * 2 + embed_dim, 64),
            nn.ReLU(),
            nn.Dropout(dropout),
            nn.Linear(64, 7),  # 输出7个污染物的预测值
        )

    def forward(self, province_ids, seq_data):
        # LSTM前向传播
        _, (hidden, _) = self.lstm(seq_data)
        # 拼接双向最后时刻的隐藏状态
        last_hidden = torch.cat([hidden[-2], hidden[-1]], dim=-1)
        # 省域嵌入
        province_emb = self.province_embed(province_ids)
        # 特征融合
        combined = torch.cat([last_hidden, province_emb], dim=-1)
        # 输出预测
        prediction = self.fc(combined)
        return prediction
```

### 4.4.2 数据集处理代码

以下是数据集处理的核心实现代码，展示了时间特征提取和样本构建：

```python
def get_time_features(date_str):
    """提取时间特征"""
    dt = datetime.strptime(date_str, "%Y-%m-%d")
    day_of_year = dt.timetuple().tm_yday
    month = dt.month
    week = dt.isocalendar()[1]
    day_of_week = dt.weekday()

    # 周期性特征
    sin_doy = math.sin(2 * math.pi * day_of_year / 365)
    cos_doy = math.cos(2 * math.pi * day_of_year / 365)
    sin_dow = math.sin(2 * math.pi * day_of_week / 7)
    cos_dow = math.cos(2 * math.pi * day_of_week / 7)
    sin_month = math.sin(2 * math.pi * month / 12)
    cos_month = math.cos(2 * math.pi * month / 12)

    # 季节特征（1-4代表春夏秋冬）
    season = (month % 12 + 3) // 3
    season_onehot = [0.0] * 4
    season_onehot[season - 1] = 1.0

    return [sin_doy, cos_doy, sin_dow, cos_dow, sin_month, cos_month] + season_onehot
```

@app.get("/api/cities/predict")
async def predict_city_air_quality(cityname: str):
    """预测城市空气质量"""
    try:
        # 加载模型（如未加载）
        if model is None:
            load_model()

        # 获取城市对应的省份

        # 执行预测
        pred = predict(province, seq_data)

        # 反缩放
        scales = dataset_scales.get(province, {})

        return {"code": 500, "msg": str(e), "data": {}}

### 4.4.4 前端图表渲染代码

以下是雷达图渲染的核心实现代码：

```javascript
function renderPredictRadar(indicators) {
    const indicatorKeys = ['pm25', 'pm10', 'so2', 'no2', 'co', 'o3'];
    const severeThreshold = {
        'pm25': 250, 'pm10': 420, 'so2': 1600,
        'no2': 565, 'co': 36, 'o3': 800
    };

    // 将实际值转换为相对严重标准的百分比
    const values = indicatorKeys.map(key => {
        const val = indicators[key];
        const threshold = severeThreshold[key];
        return (val / threshold) * 100;
    });

    const option = {
        radar: {
            indicator: indicatorNames.map(name => ({ name, max: 100 })),
            radius: '65%',
        },
        series: [{
            type: 'radar',
            data: [{
                value: values,
                name: '污染程度%',
                areaStyle: { color: 'rgba(24, 144, 255, 0.25)' },
            }]
        }]
    };

    chart.setOption(option);
}
```

## 4.5 系统测试与效果展示

系统开发完成后进行了全面的功能测试，包括单元测试和集成测试。

集成测试针对API接口和页面功能进行，包括：实时数据展示测试，验证地图加载、数据展示、交互功能的正确性；历史数据查询测试，验证日期范围选择、图表渲染的正确的；预测功能测试，验证预测请求、模型推理、结果展示的完整性。

测试结果表明，系统各项功能运行正常，能够满足设计要求。

### 5.5.2 性能测试

系统的性能测试关注响应时间和并发处理能力。

对于实时数据API（/api/cities），使用缓存时响应时间约为50-100ms，不使用缓存时响应时间约为500-800ms（取决于外部API的响应速度）。

### 5.5.3 效果展示
